# 发布执行规则

本文是智能体执行发布操作时的强制约束。

## 授权边界

以下操作可以在用户要求“准备发布”时执行：

- 读取代码、版本、变更记录和 Git 状态；
- 运行 Bash 语法检查、自动化测试和本地冒烟测试；
- 更新版本文件、变更记录和发布文档；
- 生成本地发布包及 SHA256。

以下操作必须由用户明确要求后才能执行：

- `git commit`、创建或删除 tag；
- `git push`、`gh release create`；
- 上传包到远端主机；
- 在真实主机安装、升级、创建、停止或删除实例；
- 执行 `myas/tools/release.sh`，因为它会远端部署并重建 `psftdb`。

实例授权只覆盖用户在本次对话中明确点名的实例；“删除测试实例”“清理残留”等概括性
要求不构成授权。主机上正在使用的数据库（例如 `192.168.23.4` 的 `ys1903`/psftdb、
`ys1907`/gbkdb、`ys1950`、`ys1960`）默认保留，详见 `myas/docs/MYAS-AGENT-GUIDE.md` 的
“实例清理边界”。

## 安全规则

1. 开始前执行 `git status --short`，保留用户已有修改。
2. 不使用 `git reset --hard`、`git checkout --` 或无范围的递归删除。
3. 不读取或输出密码内容；只检查凭据文件是否存在及权限是否为 `600`。
4. 命令输出包含密码、主机清单或生产路径时，记录前必须脱敏。
5. 正式发布包必须保留 `__MYAS_SYS_PASSWORD__` 占位符。
6. 测试报告结论不是 `PASS` 时停止正式发布。
7. 任何命令返回非零时，记录失败命令和输出，分析原因后再决定是否重试。

## 状态词

- `PASS`：步骤全部满足完成条件。
- `FAIL`：已验证存在问题，后续发布停止。
- `BLOCKED`：缺少授权、凭据、主机或外部信息，等待补充。
- `NOT RUN`：尚未执行，不能视为通过。

## 每步报告格式

```text
步骤：
状态：PASS | FAIL | BLOCKED | NOT RUN
执行命令：
关键结果：
产物：
遗留问题：
```

最终答复必须说明已修改文件、测试结果、未执行事项和需要用户授权的下一步。
